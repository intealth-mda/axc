# Cellix alignment review

Complete in the existing [run record](../../../harness-run-workflow.md#one-working-record), before final verification. Reference existing rows/evidence; do not copy requirements into another matrix. Mark each applicable rule in [shared architecture](shared-architecture.md), [command workflows](command-workflows.md) when triggered, and [behavioral evidence](behavioral-evidence.md) satisfied or open, with exact source/test evidence. Explain inapplicability. Missing or unexplained differences are defects.

1. **Reference:** Which exact source slice was inspected, why is it behaviorally closest, and which Cellix capabilities are reused? Compare planned/reference/implemented trees, parent/sibling composition, suffixes, exports, interfaces, context names, seedwork inheritance, tests, and behavior. Account for every omission.
2. **Domain:** Confirm identity/lifecycle classification for every concept, including query-only business objects versus derived projections; aggregate creation versus reconstruction, props/references, constrained values, child lifecycle, authorization/events/versioning, and transition ownership.
3. **Layers:** Trace API-injected factories, named service interfaces/API aliases, separate curried operation files and public contracts, query/domain data sources, repository composition, fixtures, thin transport, and independent application failure codes mapped to HTTP. No persistence types leak into public service contracts or transport.
4. **Commands:** Trace record → props adapter → converter → aggregate, repository creation/retrieval/save, scoped transactions, unit-of-work wiring, and entity exports. Inspect focused tests for each responsibility and nested history round trips, plus applicable commit/rollback/isolation/serialization/copy semantics. Unit-of-work or HTTP tests alone are insufficient.
5. **Evidence:** For each acceptance criterion and material rule, identify the owning-layer evidence and plausible wrong implementation it rejects. Check independent predicates/counterexamples, exact results, quantified executed inputs/counts (including A-AC11), direct invalid mutations with unchanged state, composed host acceptance, specified status/code, and material audit fields. Record high-risk mutation/fault-injection decisions. Check required rendered docs against endpoint contracts.
6. **Deviations:** Number each affected file/package, why the reference does not apply, chosen alternative, and cost of later alignment. Justified deviations are review evidence, not automatic failures.
7. **Completion:** Resolve all applicable architecture/evidence obligations above; no recreated Cellix capability or business/fixture logic in composition roots. Follow AGENTS completion and security policy. Record full-gate/focused results, final Biome and Knip findings versus baseline, unavailable scans, remaining issues, and boundary/whitespace checks. Do not report completion while product failures or missing applicable evidence remain.
