# Code to a sheet

Walk the code back into one workbook. Do not change the product files. One subdomain, several subdomains, and every subdomain in the repo all go in that same workbook.

The file is `<identifier>-system-design-details-output.xlsx` at the repo root. `<identifier>` is `scope` in `factory.json` with the leading `@` removed. That path is the workbook [excel/write.md](../excel/write.md) edits. Do not write a second workbook for another object.

1. Open the mongoose schema and `<Subdomain>Props`, then each nested props interface. The paths are in [field-edits.md](../field-edits.md) under "Find the files". The collection name is the mongoose `collection` option. Root `_id` and root `schemaVersion` come from that model, which extends `MongooseSeedwork.Base`. They are the first property rows. `schemaVersionDataType` uses that path's `required` and `default`. Do not take `_id` from the aggregate. The object sheet is the full schema tree, in path order, in the same row grammar `read` returns. Include every nested path. An array without `_id: false` is an entity block. `NestedPathOptions` is a value block. Do not stop at the root scalars.
2. Fill the rows from the prop table in [field-types.md](../field-types.md) under "From code back to rows". Row grammar and the header, with no role column, are in [sheet-layout.md](../sheet-layout.md). Set `contextTitle` to the context's display name and `title` to the subdomain's display name. When the model has no separate context title, both are the object sheet title.
3. Follow [excel/write.md](../excel/write.md). The only file is the workbook. Do not save a JSON file. One model writes one object sheet. Several, or the whole repo, write one Overview and one object sheet per subdomain. Send them as `{ "overviewTitle": "<dictionary title>", "documents": [ ...models ] }`. A single model may carry `overviewTitle` itself. `overviewTitle` is the cover on the Overview sheet. Copy it from the existing dictionary when one exists. In this repo that cover is `Pathways Data Dictionary`. The whole repo means every aggregate that has a mongoose model, each as one entry in `documents`. Models that share `contextTitle` share one Overview card, and each subdomain is another link in that card. The card shape, the rails, and the spacer are in [sheet-layout.md](../sheet-layout.md). Copy `access` from a prior `read` of this sheet when the role letters have to be kept. Leave them blank otherwise. Do not invent `C` `R` `U` `X`.
